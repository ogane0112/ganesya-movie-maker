# 解説動画を作る

このリポジトリの CLI `gmm`（`./bin/gmm.mjs`）で、台本（Markdown）から解説動画を作る。
タイミングは音声の長さで自動的に決まるので、台本には「何を言い、何を見せるか」だけを書く。

台本の書き方は [references/script-format.md](references/script-format.md)、
キーフレームを見るときの確認項目は [references/review-checklist.md](references/review-checklist.md)。

## 進め方

### 1. 前提をそろえる

- VOICEVOX エンジンが動いているか確かめる: `curl -s localhost:50021/version`
  動いていなければ起動する（例: `docker run -d --rm -p 50021:50021 voicevox/voicevox_engine:cpu-latest`）。
  検査とキーフレームは無音の仮音声でも動くが、MP4 の書き出しには VOICEVOX が必要
- ずんだもんの立ち絵を使うなら `characters/zundamon/layers.json` があるか確かめる。
  なければ利用者に立ち絵 PSD を頼み、`./bin/gmm.mjs character import <psd> characters/zundamon` で取り込む。
  用意できなければ `character: builtin`（組み込みキャラ）で進め、そのことを伝える
- 誰向けの動画か（前提知識）と、長さの目安（既定は 3〜5 分）がわからなければ聞く

### 2. 構成を決める

台本を書く前に、シーンの並びを箇条書きで決める。基本の流れ：

1. 表紙（`:::title`）とあいさつ
2. 今日の内容（3項目まで）
3. 前提となる概念の説明
4. 問題・つまずきどころ（なぜ大事か）
5. 悪い例 → 良い例（コード・図）
6. 応用・工夫
7. まとめ（3項目まで）→ エンディング

1シーンは 2〜4 文。1文はおよそ 4 秒なので、3〜5 分ならおよそ 15〜20 シーン・45〜60 文になる。

### 3. 専門用語を洗い出す（必ず行う）

解説動画では、**専門用語は必ず一度、最初に使う所で説明する**。

- 構成の段階で、視聴者が知らないかもしれない語を列挙し、台本のフロントマターの `glossary:` に「用語: 一言の説明」で書く
- 台本を書いたら `./bin/gmm.mjs terms <台本>` で、カタカナ語・英字の語の候補を見て、漏れている用語を `glossary:` に足す
  （漢字の語、例えば「冪等性」は候補に出ないので自分で拾う）
- 説明する文の文頭に `{term:用語}` を付ける。中心になる概念は `:::term` の用語カードで画面にも出す
- 説明は、その用語を使う最初のシーンで行う。説明の文は「〇〇は、△△のことなのだ。」のように一文で言い切る
- 表紙・エンディング（`:::title` のあるシーン）で題名として使うのは構わない
- `gmm check` が、説明のない用語（エラー）と、説明より前のシーンでの使用（警告）を見つける

### 4. 台本を書く

[references/script-format.md](references/script-format.md) に沿って `examples/` か利用者が指定した場所に書く。要点：

- 画面にはキーワードだけ、説明はナレーションで。箇条書きは 1 画面 3〜4 項目
- 部品は `{n}`（n 番目の文が始まるとき）で出す。話している内容と画面を合わせる
- 文の頭の `{face:…}` で表情を変える。驚き・困りの後は話の区切りで `{face:normal}` に戻す
- 読み間違えそうな語は `readings:` か `{表記|よみ}` で読みを指定する
  （確かめるには `curl -s -X POST "localhost:50021/audio_query?speaker=3&text=<URLエンコードした文>"` の結果の `kana` を見る）

### 5. 検査とキーフレームで直す（合格するまで繰り返す）

```sh
./bin/gmm.mjs check <台本>       # 終了コード 2: 書式エラー / 1: 検査エラー / 0: 合格（WARN も原則直す）
./bin/gmm.mjs frames <台本>      # build/<台本名>/frames/overview.png を画像として見る
./bin/gmm.mjs frames <台本> --steps --scene s05   # 気になるシーンを文ごとに見る（字幕もここで確認）
```

- `check` の `→` のヒントに従って台本を直す。音声は変えた文だけ作り直されるので、何度回してもよい
- 合格しても、[references/review-checklist.md](references/review-checklist.md) の項目を overview.png で必ず目で確かめる。
  数値の検査では見つからない問題（話と画面の順番のずれ、表情の不一致、空白の偏り）がある
- ツール自体の不具合（検査が見逃した・描画が崩れた）に気づいたら、台本でごまかさず利用者に伝える

### 6. 書き出して渡す

```sh
./bin/gmm.mjs render <台本>      # build/<台本名>/video.mp4。2回目以降は変わったシーンだけ書き出す
```

- 3〜5 分の動画の初回書き出しは数分かかる。バックグラウンドで実行して待つ
- 渡すときは、動画・`frames/overview.png`・`subtitles.srt` と、`credits.txt` のクレジット表記（概要欄に載せる）を添える
- 「確認したこと」と「確認していないこと」（例: BGM は未指定）を分けて伝える
