# 検査とキーフレームで直す（合格するまで繰り返す）

キーフレームの確認項目は [references/review-checklist.md](references/review-checklist.md)。

## 入力

- 台本（解説動画・ゲーム実況のどちらでも）

## 手順

```sh
./bin/gmm.mjs check <台本>       # 終了コード 2: 書式エラー / 1: 検査エラー / 0: 合格
./bin/gmm.mjs frames <台本>      # build/<台本名>/frames/overview.png を画像として見る
./bin/gmm.mjs frames <台本> --steps --scene s05   # 気になるシーンを文ごとに見る（字幕は文ごとの画像にだけ出る）
```

- VOICEVOX がなくても `--tts silent` で回せる（音声の長さは仮のものになる）
- モーション動画は、部品が出て落ち着いたフレームごとに測る。`--steps` で部品が出るたびの画面を見る。
  動きの途中（入り方・弾み）は画像ではわからないので、気になる場面は書き出して確かめる
- ネタ動画は、台詞・テロップが出て落ち着いたフレームごとに測る。`--steps` で台詞ごとの画面を見て、
  テロップやスタンプが顔を隠していないか、吹き出しが切れていないか、動き（倒れる・寄る）が話と合っているかを確かめる
- `check` の `→` のヒントに従って台本を直す。`[WARN]` も原則直す。音声は変えた文だけ作り直されるので、何度回してもよい
- 合格しても、確認項目を `overview.png` で必ず目で確かめる。
  数値の検査では見つからない問題（話と画面の順番のずれ、表情の不一致、空白の偏り）がある

### よく出るエラーと直し方

| ルール | 直し方 |
| --- | --- |
| `overflow` / `clipped` | 内容を減らすか、シーンを分ける。図解は語を短く・箱を減らす・`direction=TB` |
| `overlap` | 部品を減らすか、シーンを分ける |
| `subtitle-lines` / `long-sentence` | 文を短く分ける |
| `term-*` | `gmm-terms` |
| `face-long` | 話の区切りで `{face:normal}` に戻す |
| `lag`（ゲーム実況） | 前の発言を削るか短くする。映像と話がずれるので必ず直す |
| `past-end`（ゲーム実況） | 終わりの発言を減らす |
| `note-long`（ゲーム実況） | 小ネタを 60 文字以内に縮めるか、2つに分ける |
| `motion-narration-long`（モーション） | `beats=` を増やすか省略する（ナレーションに合わせる） |
| `kinetic-long` / `kinetic-fast`（モーション） | 大きな文字の行を短く分ける／`every=` を増やす |
| `text-overlap`（モーション） | 文字の置き場所（`area=`）を分けるか、出す拍をずらすか、場面を分ける |
| `caption-long`（ネタ動画） | 大きなテロップを 14 文字以内に。`\n` で 2 行に分けるか短い言葉に |
| `short-visible`（ネタ動画のテロップ） | 次のテロップを後ろの台詞にずらすか、`!wait` で間を置く |
| `stamp-long`（ネタ動画） | スタンプは 6 文字まで。長い言葉は `!caption` に |
| `overflow`（モーション。文字が端から出る） | 文字を短く、`size=` で小さく。場面のコードなら配置を直す |

- ツール自体の不具合（検査が見逃した・描画が崩れた）に気づいたら、台本でごまかさず利用者に伝える

## 終わりの条件

- `gmm check` の終了コードが 0 で、`[WARN]` も直した（直さないものは理由を言える）
- 確認項目を全部見た
- 次は `gmm-render`
